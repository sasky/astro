# Phase 8: QA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the polish items carried forward from Phases 4–7, then audit the whole site for accessibility (axe, keyboard, reduced motion, no JS), performance (Lighthouse mobile) and fidelity to the design boards (a side-by-side compare sheet for Cam).

**Architecture:**
- **Polish first (Tasks 1–3),** so the audits (Tasks 4–6) run on the finished pages.
- **Audits are lasting tests where they can be:** axe, keyboard, reduced-motion, no-JS and network checks go in `tests/e2e/`. Lighthouse and the compare sheet are one-off tools that write to `qa/` (gitignored).
- **The compare sheet** screenshots the `.dc.html` boards straight from disk. A shim rebuilds each board's `{{…}}` values from its inline `renderVals()` and the `data-props` defaults (their `support.js` isn't in the handoff), and expands the `sc-for`/`sc-if` templates the TagSelector board uses.

**Tech Stack:** Astro 7.3.4, Vitest 5, Playwright 1.64, `@axe-core/playwright` (new dev dependency), Lighthouse via `npx` (pinned version, not installed).

**Spec:**
- [`docs/redesign-plan.md`](../../redesign-plan.md): tasks 8.1–8.3, Global constraints (accessibility), Review focus 5 (no JS), 5.13 (copy button). It wins on conflicts.
- Roadmap carry-forwards (`docs/redesign-roadmap.md`, "Carried forward"): the Phase 4 test tightening, Code copy-button polish, small Code accessibility items, the Phase 6 and Phase 7 review minors, and the Fraunces SOFT/WONK check.

## Calls made in place of a brainstorm

Cam's standing preference is to skip the brainstorm Q&A and review these calls with the PR.

1. **Copy without the Clipboard API:** when `navigator.clipboard` is missing or refuses, the button falls back to `document.execCommand("copy")`, setting the exact text on the copy event (label "copied"). Only if that fails too does it select the block's code, with the label "selected" for 2s, so the reader can press ⌘C/Ctrl+C.
2. **Copy buttons without JS:** rendered `hidden`; the script reveals them. Without JS there's nothing to press.
3. **Each copy button** is described by its block's caption (`aria-describedby`), so it's announced as "copy, ── composer.json".
4. **Decorative prefixes** (`#`, `>`, `<!-- -->`) in Code descriptions, cards and the listing's list heading are `aria-hidden`. The `~/code` paths stay readable: they're part of the prompt text.
5. **Sticky TOC** gets `max-height: calc(100vh - <its top offset> - 24px)` and scrolls inside when longer.
6. **On `##` headings:** `onTips` wraps a non-tip On `h2`'s content in `<span class="h-text">`, so inline markup stays together inside the flex row. Tip numbers must be 1 or more; `## 0. Foo` stays a plain heading.
7. **On programme titles** at ≤760 use `min(24px, 13cqi)` of their text column, as the post title does.
8. **On duplication:** `.on-wrap`, `.presents` and the two hover fills (`--on-hover-fill`, `--on-active-fill`) move into `on.css`.
9. **The current tag** keeps the navy fill and adds an orange underline bar (`inset 0 -3px 0`), which a hovered tag doesn't have. One `aria-current` per row stays: each row's tag list is its own set.
10. **Page titles** come from one helper, `pageTitle(...parts)`, which appends `SITE.name` (Home stays `sasky.nz — Home`).
11. **Pico-8:** no code change. Scrolling the frame to the top on touch start is left for Cam's real-phone test (spec 6.3), since the behaviour depends on the device.
12. **Compare sheet:** boards load from `file://` (no server needed) and fetch Google Fonts as designed. TagSelector is compared against Home's `#tags` section at the board's 1040px width. Pairs are full-page at 1280×900 and 390×844.
13. **Lighthouse** runs against `astro preview`, mobile preset, with Playwright's Chromium (`CHROME_PATH`). The reports go to `qa/lighthouse/`; the PR gets the score table.

14. **Fonts (found by Lighthouse):** Fraunces comes from Google Fonts with only the `opsz` and `wght` axes, as the boards load it (Fontsource only serves its "full" font, twice the size). Source Sans 3 and JetBrains Mono become variable fonts (one file per style). Oswald is preloaded on On pages, so the subtitle doesn't reflow when it arrives.
15. **Favicon:** `public/favicon.svg`, the HP mark (orange square, blue shadow), linked from `BaseLayout`. The old site had none, so `/favicon.ico` 404'd.
16. **Tag chips** are named by what they show ("music 2 posts", with " posts" visually hidden) rather than an `aria-label`, so voice control matches.
17. **Code comments and punctuation** move to AA greys: `#6f8a7a` and `#687f71` (the spec already made the same change for the intro text).

18. **Compare fixes (Task 6):** where the sheet showed a real mismatch, the site now follows the board: tag rows 72px tall (the board's 44px is content-box), arrows drawn in the system face, the On post's subtitle, tip headings and Further heading at their desktop sizes on phones (the board shrinks only the title, numerals and Now Showing), the post board's own kraft paper (edge-burnt, no centre crease), the TOC back link grey like the TOC links, and the Code footer's 32px sides at 390.

## Global Constraints

- Astro 7 APIs only, no UI framework. Client JS stays small vanilla modules.
- **Accessibility:** touch targets at least 44px; visible `:focus-visible`; `aria-current="page"` on the current listing, `"true"` on the section link from a post; `prefers-reduced-motion` turns off blinking cursors, hover lifts and transitions.
- **Theme isolation:** each page loads only its theme's CSS and fonts; Home also loads the door faces (Holtwood One SC, Oswald, JetBrains Mono).
- **Breakpoints:** 480, 760 and 900 only.
- **No post copy changes.**
- **Performance targets (8.3):** performance ≥ 95; CLS < 0.05; only that theme's font files (plus Home's door faces); hero image ≤ rendered size × DPR; no third-party requests before interaction.
- **Axe (8.2):** zero serious or critical violations on every page type.

## Review Focus

1. **No JS:** the tag selector shows the default tag's list with chips as links; video cards link to YouTube; copy buttons don't show. Test: Task 4 no-JS spec.
2. **Reduced motion:** no blinking cursor, no hover lift, no transitions anywhere. Test: Task 4 reduced-motion spec over every page type.
3. **A clipboard that refuses** (permissions, insecure context) still leaves the reader a way to copy. Test: Task 1 e2e with `navigator.clipboard` removed and with `writeText` rejecting.
4. **A Code section with one post** renders no empty "More in Code" nav. Test: Task 1 unit.
5. **Third-party requests before interaction** (YouTube, ytimg, Google Fonts) never happen on the built site. Test: Task 5 network spec on every page type.
